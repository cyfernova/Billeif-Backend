# Negotiation Test Guide - Buyer and Seller Agents

This file contains test cases and HTTP request examples for negotiating between buyer and seller agents.

## Prerequisites

Before running negotiations, you need:
1. **Authenticated user with valid JWT token** - requires registration + email verification + login
2. Business profile created
3. Two trading agents created:
   - Buyer agent (agent_type: "trading")
   - Seller agent (agent_type: "trading")

**Authentication Flow Summary**:
1. Register user → receives verification code via email
2. Verify email using code
3. Login with email/password → receives JWT access token
4. Use JWT token in Authorization header for subsequent requests

## Test Case 1: Complete Negotiation Flow

### Setup Requests

#### 1. Register User
```bash
POST /api/v1/auth/register
Content-Type: application/json

{
  "email": "test@example.com",
  "password": "TestPass123!",
  "name": "Test User"
}

# Response: 201 Created
{
  "user_id": "user-uuid-here",
  "message": "Please verify your email address"
}
```

**Important**: After registration, you will receive a verification code via email. You MUST verify your email before you can login.

#### 2. Verify Email (Required Before Login)
```bash
POST /api/v1/auth/verify-email
Content-Type: application/json

{
  "email": "test@example.com",
  "code": "123456"
}

# Response: 200 OK
{
  "message": "email verified successfully"
}
```

**Notes**:
- The verification code is sent to the email address provided during registration
- Check your email inbox (and spam folder) for the code
- Code is typically 6 digits
- If you didn't receive the code, use the resend verification endpoint (see below)

## Test Data Summary

### Agent Volatility Levels
- Low volatility (0.0-0.3): Conservative pricing, small discounts
- Medium volatility (0.3-0.7): Moderate negotiation range
- High volatility (0.7-1.0): Aggressive pricing, large discounts possible

### Validation Rules
- Buyer proposals must be: > 30% of initial amount AND <= current amount
- Seller proposals must be: <= 150% of initial amount AND >= current amount
- Proposed amount must be >= 0
- Max rounds: 10 (default: 5)
- Negotiation expires: 24 hours after creation

### Negotiation Status Flow
1. `initiated` - Created, no rounds yet
2. `in_progress` - At least one counteroffer submitted
3. `accepted` - Both parties agreed on price
4. `rejected` - One party rejected
5. `expired` - Max rounds exceeded OR 24 hours passed

## Quick Test Script (curl)

```bash
# Set variables
export TOKEN="your-jwt-token-here"
export BUYER_ID="buyer-agent-uuid"
export SELLER_ID="seller-agent-uuid"
export API_URL="http://localhost:8080/api/v1"

# Create negotiation
curl -X POST $API_URL/bargaining/negotiations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "buyer_agent_id": "'$BUYER_ID'",
    "seller_agent_id": "'$SELLER_ID'",
    "initial_amount": 1000.00,
    "max_rounds": 5
  }' | jq

# Extract negotiation_id from response
export NEG_ID="paste-negotiation-id-here"

# Buyer counteroffer
curl -X POST $API_URL/bargaining/negotiations/$NEG_ID/counteroffer \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "agent_id": "'$BUYER_ID'",
    "proposed_amount": 800.00,
    "action": "counteroffer",
    "reason": "Need discount"
  }' | jq

# Seller counteroffer
curl -X POST $API_URL/bargaining/negotiations/$NEG_ID/counteroffer \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "agent_id": "'$SELLER_ID'",
    "proposed_amount": 950.00,
    "action": "counteroffer",
    "reason": "Quality premium"
  }' | jq

# Seller accepts
curl -X POST $API_URL/bargaining/negotiations/$NEG_ID/counteroffer \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "agent_id": "'$SELLER_ID'",

# Get all rounds
```

# Agent Creation JSON Format (UPDATED)

## Important: Agent Creation Request Format

The note.txt above contains OUTDATED trading agent examples. The correct format for creating agents is:

### Valid Agent Types
- `shopping` - Personal shopping agent
- `merchant` - Business/merchant agent  
- `buyer` - Buyer agent for bargaining
- `seller` - Seller agent for bargaining
- `credential_provider` - Credential management agent
- `payment_processor` - Payment processing agent

### Field Name: `type` (NOT `agent_type`)

Use `type` field, not `agent_type`:
```json
{
  "type": "seller",  // NOT "agent_type"
  "name": "Seller Agent 1",
  "description": "Description here",
  "config": {
    "volatility": 0.7,
    "strategy": "conservative"
  }
}
```

### Do NOT Send ID When Creating
Remove the `"id": "seller-agent-uuid"` field from create requests. ID is auto-generated by the database.

### Config Should Be Object, Not String
```json
// CORRECT:
"config": {
  "volatility": 0.7,
  "strategy": "conservative"
}

// WRONG:
"config": "{\"volatility\":0.7,\"strategy\":\"conservative\"}"
```

## Correct Examples

### Create Buyer Agent
```json
{
  "type": "buyer",
  "name": "Buyer Agent 1",
  "description": "Buyer agent for negotiations",
  "config": {
    "volatility": 0.3,
    "strategy": "aggressive"
  }
}
```

### Create Seller Agent
```json
{
  "type": "seller",
  "name": "Seller Agent 1",
  "description": "Seller agent for negotiations",
  "config": {
    "volatility": 0.7,
    "strategy": "conservative"
  }
}
```

### Create Shopping Agent
```json
{
  "type": "shopping",
  "name": "My Shopping Agent",
  "description": "Personal shopping assistant"
}
```

### Create Merchant Agent
```json
{
  "type": "merchant",
  "name": "My Merchant Agent",
  "description": "Business merchant agent",
  "product_ids": []
}
```

## Common Errors and Fixes

### Error: "type is required"
**Cause**: Using `agent_type` instead of `type`
**Fix**: Change `"agent_type": "seller"` to `"type": "seller"`

### Error: "invalid agent type"
**Cause**: Using unsupported type like "trading"
**Fix**: Use valid types: buyer, seller, shopping, merchant, credential_provider, payment_processor

### Error: EOF or connection hangs
**Cause**: Sending `id` field in create request, or config as string
**Fix**:
- Remove `"id": "..."` from request
- Make config an object: `"config": {...}` instead of `"config": "{...}"`

## Problem Description
The /api/v1/agents endpoint was returning EOF errors when called without proper authentication or when the JWT token validation failed. This was caused by:
1. Handlers attempting database queries with empty userID values
2. BusinessAuth middleware reading the request body, causing issues with API Gateway

## Test Environment
- URL: https://2msvdt2oba.execute-api.us-east-1.amazonaws.com/api/v1/agents
- Base URL: https://2msvdt2oba.execute-api.us-east-1.amazonaws.com

## Prerequisites
- Obtain a valid JWT token from AWS Cognito via /api/v1/auth/login
- Test with both authenticated and unauthenticated requests

```go
// extractBusinessID extracts business_id from query or path params.
// Note: We do not read request body here to avoid EOF issues with API Gateway/proxies.
func extractBusinessID(c *gin.Context) string {
    // Check query param first
    if id := c.Query("business_id"); id != "" {
        return id
    }
    // Check path param
    if id := c.Param("business_id"); id != "" {
        return id
    }
    return ""
}
```

- Prevents EOF issues caused by consuming request body in middleware
